- 2026-09-13 — **Task 7 partially done, and the thinking-mode guard was wrong.** The 4B is downloaded (`models/qwen3.5-4b-gguf/Qwen3.5-4B-Q4_K_M.gguf`, GGUF v3, 426 tensors, 2.74 GB, header-verified) and imported into the installed CPU-only ollama as `neiro-4b` — no sudo needed, so T7's *contract* could be tested today even though `llama-cpp`/`ggml-vulkan` still can't be installed. Result, measured against the real server: **the plan's guard would never have fired.** On `/v1/chat/completions`, ollama 0.33.2 does not put reasoning in the content as `<think>` at all — it streams it in a separate `delta.reasoning` field while `delta.content` stays `""` for the entire response. A 60-token request returned `content=''` and 60 completion tokens of invisible reasoning. A client reading only `content`, with a guard looking for `"<think"` in the text, sees a well-formed stream that produces no words, spends the whole budget, and raises nothing — silent failure with no error, the exact class of bug this project exists to design out. Worse: on that endpoint **both** documented switches were accepted and ignored — `think: false` AND `chat_template_kwargs: {enable_thinking: false}` (the two the plan and CLAUDE.md rule 4 specify). Only ollama's **native `/api/chat` with `think: false`** actually suppressed it, returning `"Hello there, friend."` with no `thinking` field at all. Fixed in `llm/openai_compat.py` with three checks instead of one: `check_delta_not_thinking()` fires on the FIRST reasoning delta (so a misconfigured backend costs one chunk, not a whole budget), `check_not_thinking()` still catches inline `<think>` for backends that do it that way, and `check_produced_words()` catches a finished stream that spent reasoning and said nothing — the case where some future backend hides it under a field name nobody has seen yet. The observed delta is pinned verbatim as a test, alongside a test asserting the *old* guard would have missed it. Consequence for the architecture: ollama's OpenAI-compatible endpoint is **not usable** for this project as-is; llama-server (`--reasoning-budget 0 --reasoning-format none`) remains the target for both tiers, and whichever backend is used must be re-verified with curl, never assumed.
- 2026-09-13 — **Lane A prosody built — the differentiator now exists in code.** `affect/{features,baseline,prosody,null}.py`, 39 tests. Seven features per window (median F0, F0 IQR, RMS mean/p95, voiced ratio, pause ratio, onset rate as a transcript-free pace proxy), scored as robust z-scores against a rolling per-device baseline of Yash's own voice. Design choices that are load-bearing rather than stylistic: **median and MAD, never mean and standard deviation** — one shout would drag a mean for the rest of the day, and a test asserts a single loud utterance moves the baseline by <10%; **baselines keyed by capture device** — the built-in mic ran at +30 dB (see 2026-09-11), so pooling devices would make every switch look like an emotional event; **`None`, never zeros**, for any window too short, too quiet or too unvoiced, because "exactly average" and "no idea" must not be confusable when the annotation is *omitted* below the floor rather than softened; **drift detection** resets the baseline after 8 consecutive utterances at |z| ≥ 4 on every feature, with a log line — that is a different speaker or a changed gain, not an emotion; **hysteresis** requires 2 of the last 3 windows to agree before the band moves, so one mispitched syllable can't flip her face; **the baseline updates once per utterance, never per window**, or one long sentence would dominate his normal. Valence is computed but given its own explicitly lower confidence (`VALENCE_CONFIDENCE_FACTOR = 0.5`) and its own accessor, so nothing can accidentally inherit arousal's confidence — G3b measures both axes and the plan says to assume neither.
- 2026-09-13 — **librosa has the same cold-start trap as ctranslate2.** Measured: the first `affect.features.extract()` call takes **~1210 ms**, the second **~54 ms** — lazy imports plus numba compiling the pyin and onset kernels. Identical in shape to Gate G1's ctranslate2 finding (7.44 s cold → 0.36 s warm) and with the same fix: `features.warm()` runs a throwaway extraction at process start. A 1.2 s stall on the first thing Yash says in the morning is exactly the "it feels broken" failure this project is built to avoid. Also measured while choosing the algorithm: `librosa.pyin` = 47.9 ms per 3 s window vs `librosa.yin` = 2.7 ms. pyin is ~18x slower and is still the default, because it returns a per-frame voicing probability — which is what makes `voiced_ratio` and `pause_ratio` trustworthy, and because affect runs on a rolling window *while the user is still speaking* and therefore costs the turn budget nothing. `f0_algorithm` is a config key so a slower machine can disagree.
- 2026-09-13 — **Affect fusion built, after a gap analysis found it was the one uncovered piece of the emotional core.** Two lanes were designed and nothing said what happens when both exist and disagree. The real difficulty is a **unit mismatch that would have looked like it worked**: Lane A produces a *z-score* ("1.4σ louder and faster than Yash's own normal"); Lane B produces a point on the circumplex ("arousal 0.6 in [-1,1]") learned from actors who are not Yash. Averaging those is a category error. `affect/fusion.py` fixes it by **baselining Lane B too** — a rolling robust estimate of the model's predictions *on him*, z-scored with the same median/MAD machinery as the prosody baseline, so both lanes answer "how far from his usual is this?". That also silently fixes model calibration: a SER model that reads every Indian-accented voice as slightly angry has a non-zero median on him, and subtracting that median removes the bias entirely (there is a test for exactly this). Second rule: **disagreement is information, not noise** — when the lanes point opposite ways the answer is not their average but lower confidence (×0.4), which is what the prompt's "ignore it at low confidence" rule then acts on; agreement raises it (×1.25, capped). A lane inside the dead-band is *declining to say*, not contradicting, and is not counted as conflict. Lane A outweighs Lane B 0.6/0.4 until G3b says otherwise **on his recordings**: the lane that knows him personally leads over the one trained on actors.
- 2026-09-13 — **Gap analysis: eight trainable components the eleven dataset targets do not cover.** Recorded so they are decisions rather than omissions: (1) **lip-sync/viseme timing** — the six presets drive expression, nothing trains audio→viseme alignment (Kokoro gives this free, every other TTS does not); (2) **speech enhancement + AEC front-end** — barge-in over laptop speakers needs more than the RIR/noise augmentation the wake-word target covers; (3) **TTS front-end G2P and text normalisation for Hinglish** — Roman-script Hindi, ₹/number/date expansion, Indian proper nouns; (4) **affect fusion and calibration** — now built, above; (5) **long-term memory retrieval embeddings for Hinglish** — off-the-shelf English embedders degrade on Roman-script Hindi; (6) **speech-driven head motion/gaze** — beyond six presets, co-speech motion is what reads as alive; (7) **tool-action risk/prompt-injection classifier** — the persona LoRA teaches *when* to call a tool, nothing trains a risk gate; (8) **per-utterance language ID** — routing the STT prompt and TTS voice for code-switched input is not something STT fine-tuning trains implicitly. - 2026-09-13 — **Three real bugs in Lane A, all found by running it on real speech instead of synthetic tones, and all silent.** (1) `voiced_prob_floor = 0.5` — librosa's pyin `voiced_prob` is **not** a 0-1 confidence; it is posterior mass on the winning pitch candidate and peaks around **0.15** on real speech. ANDing it against 0.5 rejected **100% of real utterances** while passing synthetic tones (a pure tone concentrates the posterior). The failure looked exactly like the intended "say nothing when unsure" behaviour. (2) `frame_length = 1024` for pitch is below librosa's own `4·sr/fmin = 1067` requirement at fmin=60 — pitch now has its own `f0_frame_length = 2048`, and `_f0` raises rather than letting a config change fail silently. (3) **pyin was the wrong estimator entirely**, and it was chosen by validating on a synthetic tone — the easiest possible input for it. Measured on 60 real clips: pyin 24-28/60 usable, mean voiced_ratio 0.14-0.21, ~55 ms/clip; **yin 60/60, mean 0.99, ~3 ms/clip**. pyin's HMM is far too conservative on short (~2 s) utterances. Default is now yin for pitch with voicing decided from an energy gate on the same frame grid (pyin stays available for long clean audio). Result: 60/60 usable at **10.4 ms/clip**, and the features separate emotions correctly on speaker 1001 — SAD f0=111 Hz/rms=0.012, NEU f0=124/0.020, ANG f0=155/0.041, FEA f0=196/0.044.
- 2026-09-13 — **Drift detection required ALL features extreme, so it would never have fired.** Measured by baselining one CREMA-D speaker and scoring five others: mean max|z| per utterance is **2.32 for the same speaker** and **4.44-6.00 for every different one**, but only **1.0-1.4 of 7 features** exceed |z| ≥ 4 — a different person mostly moves *pitch* and leaves pausing and voiced ratio alone. Rule changed to **any** feature extreme; the false-positive guard is the sustained-run requirement (8 consecutive utterances), not the width of the shift. Same-speaker utterances average 0.1 extreme features, so a run of 8 is negligible.

Handled upstream instead: audio reaches the affect path only behind push-to-talk (Stage 0) and Silero VAD (Stage 2).

- 2026-09-13 — **The output half of the emotional loop built: `emotion/blend.py` and `emotion/voice.py`.** One `NeiroState` now reaches the face and the voice through code that can be tested without a browser or a TTS. **Face**: exponential approach with **asymmetric time constants** — τ 0.12 s rising, 0.30 s falling. That asymmetry is the single most important number in the file; making them equal is what makes an avatar look mechanical even when everything else is right. Measured curves: rise 0.104 at 16 ms → 0.649 at 200 ms → 0.788 at 500 ms; fall 0.757 at 16 ms → 0.294 at 300 ms → 0.029 at 1 s. `surprised` **releases itself** after 0.9 s whether or not a new state arrives (held longer it reads as a stare, not surprise) — verified decaying 0.900 → 0.119 by 2.5 s on a state that never changes. Weights are clamped in total (VRM expressions are additive on one mesh; past 1.0 the geometry looks broken) by **scaling together**, so a crossfade does not visibly jump. Weights under 0.01 snap to zero, because an exponential never quite arrives and 0.003 of "angry" left on her face all evening is a real thing. `neutral` is deliberately **not** driven as a weight — in VRM it is the rest pose, so driving it fights the others; neutral is "all five near zero". The research finding that `surprised` is often *unbound* in real VRM models is handled by `available` + a circumplex-nearest fallback (an avatar without `surprised` gets `happy`; without `angry` gets `sad`, keeping valence direction) rather than a silent no-op — a face that does nothing is indistinguishable from a bug.
- 2026-09-13 — **`emotion/voice.py`: the instruct string is a prompt, so it is pinned by tests.** Kokoro has no emotion control and Orpheus's is eight sound-effect tags, so the expressive path is Qwen3-TTS's free-form `instruct` field — which makes prose the interface. Two rules encoded: it describes **delivery, not the emotion name** ("clipped and lower, tighter, with an edge — not shouting" rather than "say this angrily", which produces a caricature), and it always opens with the same identity clause so the voice stays recognisably one person across states. Instructions are capped under 30 words because TTFA is in the measured latency budget and long instructions dilute. `exaggeration_for()` gives Chatterbox's single dial from the same state, floored at 0.25 (a completely flat reading sounds synthetic) and ceilinged at 0.8 (Chatterbox's own guidance is that high exaggeration costs intelligibility, and a voice assistant that cannot be understood is worse than a flat one). Both derive from `NeiroState` and never from each other, so gate G5 swapping the engine changes one function rather than the emotional contract.
- 2026-09-13 — **Silero VAD wired (`audio/vad.py`), with the three quiet failure modes pinned as tests.** Measured on this machine: **0.08 ms per 32 ms frame** on CPU ONNX (400x realtime, 0 VRAM — the GPU is fully committed), warm-up 1.5 ms. On real CREMA-D speech the probability spans 0.00-1.00 with mean 0.51; on digital silence mean **0.0068**, max 0.044 — a clean separation. `SpeechGate` found a real utterance starting at 480 ms and ending at 1792 ms of a 2.28 s clip. The three failures Silero produces *silently*, each now a test: (1) **frame size must be exactly 512 samples at 16 kHz** — v5 dropped other sizes and returns plausible nonsense rather than an error, so `probability()` raises `VadFrameSizeError`; (2) **it is a stateful RNN** — the 2×1×128 state must be carried in order, and dropping it makes every frame look like the start of speech, which reads as "works, but jumpy" rather than as a bug (the test asserts carried and stateless sequences differ); (3) **`reset()` between utterances**, or the tail of one biases the start of the next. Hysteresis in `SpeechGate` is asymmetric for the same reason as the expression blender — leaving speech is slower than entering it (200 ms vs 96 ms), because cutting someone off mid-sentence is much worse than a little trailing silence, and a test asserts "I want to go to… uh… the library" survives as one turn. `BargeInDetector` is stricter on every axis (p ≥ 0.85 vs 0.5, 250 ms vs 96 ms, plus a 200 ms dead zone re-armed on every reply) because a false positive cuts Neiro off mid-sentence while a false negative only costs Yash a repeat — the costs are not symmetric. VAD remains the *trigger*, never the decision: `SpeechGate` reports transitions and Stage 2's smart-turn decides whether a turn actually ended.
- 2026-09-13 — **`tools/registry.py`: the safety layer is now enforced by types, not by prose.** Three walls. **(1) Shape, checked at registration time rather than call time** — a bare `str` argument raises on import, because a tool with free-form text should stop the process on startup, not fail once in production when a 4B model finally emits the wrong thing. Arguments may be `int` (an index into a list Neiro produced *this turn*), a `Literal` enum, or a scalar; genuinely spoken text must be opted into per-field via `spoken_text_fields`. `extra="forbid"` is mandatory — an unexpected key from the model is a rejection, not something to ignore. **(2) Tier** — RED tools cannot be *registered at all*, so the model cannot express them; gating them would still let it try. A GREEN tier ceiling removes YELLOW tools from the schema list entirely, for the remote tier where confirmation is impossible. **(3) Budget** — per-tool sliding windows plus a global 30/min side-effect budget, so many individually-allowed actions cannot add up to a runaway; GREEN reads are exempt because asking the battery level forty times is pointless, not dangerous. The YELLOW confirmation nonce binds tool + arguments + turn, is computed in the registry, and is **never sent to the model**, so a reply cannot forge one — the LLM does not participate in its own authorisation. `to_openai_schema()` is generated from the same pydantic model that validates the call, so the advertised schema and the enforced one cannot drift. Tool order is sorted and stable because the tools array is part of the KV prefix — reordering it costs a full prefill (0.3-1.3 s) every turn with no error to explain the latency. The three Lua payloads proven during research to execute inside the compositor are negative tests, and the point of the test is that they cannot even be *expressed*: there is no string-typed field to put them in.
