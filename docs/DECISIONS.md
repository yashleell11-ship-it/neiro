- 2026-09-13 — **Task 7 partially done, and the thinking-mode guard was wrong.** The 4B is downloaded (`models/qwen3.5-4b-gguf/Qwen3.5-4B-Q4_K_M.gguf`, GGUF v3, 426 tensors, 2.74 GB, header-verified) and imported into the installed CPU-only ollama as `neiro-4b` — no sudo needed, so T7's *contract* could be tested today even though `llama-cpp`/`ggml-vulkan` still can't be installed. Result, measured against the real server: **the plan's guard would never have fired.** On `/v1/chat/completions`, ollama 0.33.2 does not put reasoning in the content as `<think>` at all — it streams it in a separate `delta.reasoning` field while `delta.content` stays `""` for the entire response. A 60-token request returned `content=''` and 60 completion tokens of invisible reasoning. A client reading only `content`, with a guard looking for `"<think"` in the text, sees a well-formed stream that produces no words, spends the whole budget, and raises nothing — silent failure with no error, the exact class of bug this project exists to design out. Worse: on that endpoint **both** documented switches were accepted and ignored — `think: false` AND `chat_template_kwargs: {enable_thinking: false}` (the two the plan and CLAUDE.md rule 4 specify). Only ollama's **native `/api/chat` with `think: false`** actually suppressed it, returning `"Hello there, friend."` with no `thinking` field at all. Fixed in `llm/openai_compat.py` with three checks instead of one: `check_delta_not_thinking()` fires on the FIRST reasoning delta (so a misconfigured backend costs one chunk, not a whole budget), `check_not_thinking()` still catches inline `<think>` for backends that do it that way, and `check_produced_words()` catches a finished stream that spent reasoning and said nothing — the case where some future backend hides it under a field name nobody has seen yet. The observed delta is pinned verbatim as a test, alongside a test asserting the *old* guard would have missed it. Consequence for the architecture: ollama's OpenAI-compatible endpoint is **not usable** for this project as-is; llama-server (`--reasoning-budget 0 --reasoning-format none`) remains the target for both tiers, and whichever backend is used must be re-verified with curl, never assumed.
- 2026-09-13 — **Lane A prosody built — the differentiator now exists in code.** `affect/{features,baseline,prosody,null}.py`, 39 tests. Seven features per window (median F0, F0 IQR, RMS mean/p95, voiced ratio, pause ratio, onset rate as a transcript-free pace proxy), scored as robust z-scores against a rolling per-device baseline of Yash's own voice. Design choices that are load-bearing rather than stylistic: **median and MAD, never mean and standard deviation** — one shout would drag a mean for the rest of the day, and a test asserts a single loud utterance moves the baseline by <10%; **baselines keyed by capture device** — the built-in mic ran at +30 dB (see 2026-09-11), so pooling devices would make every switch look like an emotional event; **`None`, never zeros**, for any window too short, too quiet or too unvoiced, because "exactly average" and "no idea" must not be confusable when the annotation is *omitted* below the floor rather than softened; **drift detection** resets the baseline after 8 consecutive utterances at |z| ≥ 4 on every feature, with a log line — that is a different speaker or a changed gain, not an emotion; **hysteresis** requires 2 of the last 3 windows to agree before the band moves, so one mispitched syllable can't flip her face; **the baseline updates once per utterance, never per window**, or one long sentence would dominate his normal. Valence is computed but given its own explicitly lower confidence (`VALENCE_CONFIDENCE_FACTOR = 0.5`) and its own accessor, so nothing can accidentally inherit arousal's confidence — G3b measures both axes and the plan says to assume neither.
- 2026-09-13 — **librosa has the same cold-start trap as ctranslate2.** Measured: the first `affect.features.extract()` call takes **~1210 ms**, the second **~54 ms** — lazy imports plus numba compiling the pyin and onset kernels. Identical in shape to Gate G1's ctranslate2 finding (7.44 s cold → 0.36 s warm) and with the same fix: `features.warm()` runs a throwaway extraction at process start. A 1.2 s stall on the first thing Yash says in the morning is exactly the "it feels broken" failure this project is built to avoid. Also measured while choosing the algorithm: `librosa.pyin` = 47.9 ms per 3 s window vs `librosa.yin` = 2.7 ms. pyin is ~18x slower and is still the default, because it returns a per-frame voicing probability — which is what makes `voiced_ratio` and `pause_ratio` trustworthy, and because affect runs on a rolling window *while the user is still speaking* and therefore costs the turn budget nothing. `f0_algorithm` is a config key so a slower machine can disagree.
- 2026-09-13 — **Affect fusion built, after a gap analysis found it was the one uncovered piece of the emotional core.** Two lanes were designed and nothing said what happens when both exist and disagree. The real difficulty is a **unit mismatch that would have looked like it worked**: Lane A produces a *z-score* ("1.4σ louder and faster than Yash's own normal"); Lane B produces a point on the circumplex ("arousal 0.6 in [-1,1]") learned from actors who are not Yash. Averaging those is a category error. `affect/fusion.py` fixes it by **baselining Lane B too** — a rolling robust estimate of the model's predictions *on him*, z-scored with the same median/MAD machinery as the prosody baseline, so both lanes answer "how far from his usual is this?". That also silently fixes model calibration: a SER model that reads every Indian-accented voice as slightly angry has a non-zero median on him, and subtracting that median removes the bias entirely (there is a test for exactly this). Second rule: **disagreement is information, not noise** — when the lanes point opposite ways the answer is not their average but lower confidence (×0.4), which is what the prompt's "ignore it at low confidence" rule then acts on; agreement raises it (×1.25, capped). A lane inside the dead-band is *declining to say*, not contradicting, and is not counted as conflict. Lane A outweighs Lane B 0.6/0.4 until G3b says otherwise **on his recordings**: the lane that knows him personally leads over the one trained on actors.

- 2026-09-13 — **Three real bugs in Lane A, all found by running it on real speech instead of synthetic tones, and all silent.** (1) `voiced_prob_floor = 0.5` — librosa's pyin `voiced_prob` is **not** a 0-1 confidence; it is posterior mass on the winning pitch candidate and peaks around **0.15** on real speech. ANDing it against 0.5 rejected **100% of real utterances** while passing synthetic tones (a pure tone concentrates the posterior). The failure looked exactly like the intended "say nothing when unsure" behaviour. (2) `frame_length = 1024` for pitch is below librosa's own `4·sr/fmin = 1067` requirement at fmin=60 — pitch now has its own `f0_frame_length = 2048`, and `_f0` raises rather than letting a config change fail silently. (3) **pyin was the wrong estimator entirely**, and it was chosen by validating on a synthetic tone — the easiest possible input for it. Measured on 60 real clips: pyin 24-28/60 usable, mean voiced_ratio 0.14-0.21, ~55 ms/clip; **yin 60/60, mean 0.99, ~3 ms/clip**. pyin's HMM is far too conservative on short (~2 s) utterances. Default is now yin for pitch with voicing decided from an energy gate on the same frame grid (pyin stays available for long clean audio). Result: 60/60 usable at **10.4 ms/clip**, and the features separate emotions correctly on speaker 1001 — SAD f0=111 Hz/rms=0.012, NEU f0=124/0.020, ANG f0=155/0.041, FEA f0=196/0.044.
- 2026-09-13 — **Drift detection required ALL features extreme, so it would never have fired.** Measured by baselining one CREMA-D speaker and scoring five others: mean max|z| per utterance is **2.32 for the same speaker** and **4.44-6.00 for every different one**, but only **1.0-1.4 of 7 features** exceed |z| ≥ 4 — a different person mostly moves *pitch* and leaves pausing and voiced ratio alone. Rule changed to **any** feature extreme; the false-positive guard is the sustained-run requirement (8 consecutive utterances), not the width of the shift. Same-speaker utterances average 0.1 extreme features, so a run of 8 is negligible.

- 2026-09-13 — **The output half of the emotional loop built: `emotion/blend.py` and `emotion/voice.py`.** One `NeiroState` now reaches the face and the voice through code that can be tested without a browser or a TTS. **Face**: exponential approach with **asymmetric time constants** — τ 0.12 s rising, 0.30 s falling. That asymmetry is the single most important number in the file; making them equal is what makes an avatar look mechanical even when everything else is right. Measured curves: rise 0.104 at 16 ms → 0.649 at 200 ms → 0.788 at 500 ms; fall 0.757 at 16 ms → 0.294 at 300 ms → 0.029 at 1 s. `surprised` **releases itself** after 0.9 s whether or not a new state arrives (held longer it reads as a stare, not surprise) — verified decaying 0.900 → 0.119 by 2.5 s on a state that never changes. Weights are clamped in total (VRM expressions are additive on one mesh; past 1.0 the geometry looks broken) by **scaling together**, so a crossfade does not visibly jump. Weights under 0.01 snap to zero, because an exponential never quite arrives and 0.003 of "angry" left on her face all evening is a real thing. `neutral` is deliberately **not** driven as a weight — in VRM it is the rest pose, so driving it fights the others; neutral is "all five near zero".
