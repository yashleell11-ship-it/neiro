- 2026-09-11 — **Gate G1 (Blackwell) — GO.** ctranslate2 4.8.2 on this RTX 5070 Laptop (cc 12.0): `int8_float16` is in `get_supported_compute_types('cuda')` **and** an actual `transcribe()` call ran end to end at that compute type (the first check alone is not proof — an earlier attempt reported `int8_float16` supported and then crashed with `libcublas.so.12 is not found`, because `env.sh`'s path-resolution one-liner used `nvidia.cublas.lib.__file__`, which is `None` on a PEP 420 namespace package; fixed to use `__path__[0]`). Measured on `distil-whisper/distil-large-v3.5-ct2`: model **load** 3.02s cold (ComputeCache cleared) → 1.67s warm — a small, unremarkable delta. Model **transcribe** 7.44s cold → 0.36s warm — a ~20x delta, meaning the real first-use JIT cost is paid on first *inference*, not on `WhisperModel()` construction. Correction for Stage 0 Tasks 5/7: "warm the model at process start" must include one throwaway `transcribe()` call, not just constructing the model object, or the first real user utterance eats the 7s stall instead.
- 2026-09-11 — Task 3 done — audio capture/playback plumbing built and run end to end (`src/neiro/audio/{devices,capture,playback}.py`, `neiro mic-test`). Real finding: **PortAudio does not see PipeWire node names at all** — `sd.query_devices()` only shows generic ALSA PCM aliases (`pipewire`, `pulse`, `default`, whatever hardware card is live). The pactl-style names Task 0 stores in `config.toml` are invisible to `sounddevice`'s `device=` parameter. Fix, verified working: always open the `'pulse'` PortAudio device and set `PULSE_SOURCE`/`PULSE_SINK` env vars (pipewire-pulse's standard PulseAudio-compat mechanism) to the exact node name right before opening the stream — safe to set from inside Python here, unlike `env.sh`'s `LD_LIBRARY_PATH` case, because pipewire-pulse reads them at client-connect time (stream open), not at process start. **Not yet re-verified with two devices live simultaneously** (earbuds were off/unreachable during this test — `bluetoothctl connect` timed out after 15s) — added a `--profile` override to `mic-test` so this can be tested against `speakers` without touching the saved `active_profile`; re-run against `earbuds` once they're reachable, ideally as part of Gate G4 (Task 14) where both profiles get tested deliberately anyway.
- Measured on the `speakers` profile (built-in mic, unmuted for this test): a 3s recording at normal speaking volume peaked at **1.22** (float32, i.e. clipping — anything over 1.0 has saturated). `amixer -c0`: Capture gain is at 63/63 (100%, +30dB) and Internal Mic Boost is enabled. This is the same +30dB finding an earlier research pass flagged as a clipping risk for AEC — confirmed here with a real recording. Not fixed as part of Task 3 (out of scope — lowering system mic gain is a one-line `amixer`/`wpctl` fix, but changing it isn't part of proving the plumbing works); flagged for Task 14 (AEC) and Task 6 (WER set), since clipped input degrades both transcription and the prosody features Gate G3b depends on.
- Human-ear verification (the part I cannot check myself): recording sent to Yash for confirmation that playback 1 sounded correct and playback 2 sounded sped-up/pitched-up.
- 2026-09-11 — Task 4 done — terminal push-to-talk built (`src/neiro/audio/ring.py`, `src/neiro/audio/ptt.py`, `neiro ptt`), with `pre_roll_s`/`ring_buffer_seconds` added to `AudioConfig`. `RingBuffer` has 21 passing tests including wraparound stitching — the one piece of this task with real logic worth pinning down before Stage 1's endpointer reuses it at a larger capacity. `neiro ptt` needs a genuine interactive terminal (raw-mode, byte-at-a-time keyboard reads via `termios`/`tty`/`select`) — confirmed it fails with a clean, readable message rather than a `termios` traceback when run without a TTY (exactly the situation running it via an automated tool produces), so this is the same kind of check as Task 3's chipmunk test: proven mechanically as far as it can be from here, the live "does the bar move, is the first word intact" verification is Yash's to run in his own terminal.
